## Design Specificity Verdict

**LLM assessment: category-interchangeable. This is a Tailwind starter with support-ticket words poured into it.**

The test: rename it "Bug Tracker Pro" / "CRM Lite" and not one pixel changes. It fails.

- `index.css` is 17 lines — no design tokens, no type scale, no custom properties. Every value is a raw Tailwind default.
- No font decision. `index.html` loads no webfont, no favicon, no meta description. Renders in the OS system stack.
- No iconography — the only SVG in `src/` is the `Spinner`.
- Nothing about AI is visual. The AI analysis panel is the same `rounded-xl border-slate-200 bg-white p-5 shadow-sm` card as the customer email address below it. Overview's "AI pipeline" is a 2x2 grid of gray boxes.
- Portal and admin headers are identical except a 12px gray subtitle.

**Deterministic scan:** 0 findings, exit code 0 across 4 invocations. No suppression config, no inline ignores; re-ran with `--no-config --no-inline-ignores` → still `[]`. Zero false positives.

**Divergence:** the detector proves there is no visual slop; the design review finds there is no visual identity. Clean is not authored. The detector measures anti-patterns and cannot measure specificity, which is the actual problem.

## Overall Impression

The plumbing is genuinely good — shared primitives hold across 16 pages, error copy branches on real status codes, the close-ticket confirmation is better-engineered than most production admin tools. The art direction essentially does not exist, and one functional gap (P0) severs the product's core loop. Biggest opportunity: make AI provenance visible — that is the entire thesis and it has no visual grammar.

## What's Working

1. `ui.tsx` primitives hold across 16 pages — no hand-rolled input/button styling except the deliberate danger variant; focus rings, error placement, control rhythm pixel-identical between LoginPage, NewTicketPage, AdminWorkflowFormPage.
2. Error copy branches on real API status: 401 → "Invalid email or password."; 409 → "try signing in instead"; `api.ts:37-48` flattens FastAPI 422 arrays into sentences.
3. The ticket-close confirmation: amber consequence notice → button morphs to red "Confirm close" → auto-disarms if the status select changes.

## Priority Issues

**[P0] Admins can never send a reply — the AI suggested response is a dead end.**
Why: `addTicketMessage` is imported only by `portal/TicketDetailPage.tsx` (verified directly). The admin conversation is a read-only `<ol>`. An admin can edit a suggested response and click Save & confirm, then has no way to deliver it. AI triages → human confirms → customer gets helped: steps 2 and 3 are severed; the "Human-confirmed" badge confirms text that goes nowhere.
Fix: add a reply composer below Conversation on `AdminTicketDetailPage`, plus a "Use as reply" button that copies `analysisDraft` into it.
Suggested command: `/impeccable shape admin reply + AI handoff`

**[P1] "Awaiting review" is a dead end — the triage queue does not exist.**
Why: the four status cards are `<Link>`s to filtered lists; `awaiting_review` is a plain static KpiCard. The admin sees "7 awaiting review" and cannot reach those tickets. The number that justifies the product has less affordance than "Closed: 4".
Fix: link the KPI, add a review-state segment to the filter group, add an `AI: pending/failed/needs review/confirmed` column to the ticket table.
Suggested command: `/impeccable layout triage queue`

**[P1] Workflow delete arms a confirm with zero warning.**
Why: the armed branch renders only a Cancel button — no amber notice, unlike the close-ticket flow. Only irreversible data-loss action; Delete → Confirm delete in rhythm gives no second chance and no explanation at decision time.
Fix: amber notice naming exactly what dies (workflow + run history; tickets untouched) before the second click counts. Better: require typing the workflow name.
Suggested command: `/impeccable harden destructive confirms`

**[P1] Every load failure says "Refresh the page" — and nothing in the UI can refresh.**
Why: 10 occurrences across 8 files, no retry button anywhere. Detail pages offer only a navigation link, so recovery means losing position (and on Analytics, the 7/30/90-day window).
Fix: shared `LoadError({ message, onRetry })` in `ui.tsx` with `role="alert"` + "Try again". Retry pattern already exists as `reloadTicket`.
Suggested command: `/impeccable harden error states`

**[P2] Three competing "selected" visual languages.**
Why: `bg-slate-900` pill (ticket filters) vs `bg-emerald-600` pill (analytics window) vs emerald underline (nav). On an Operate surface "this is the current selection" must be learnable once and transferred everywhere.
Fix: one `activePillClass` in `ui.tsx`, emerald, applied to both filter groups.
Suggested command: `/impeccable extract shared primitives`

## Persona Red Flags

**Alex (power user)** — `AdminTicketListPage` is a throughput dead end: no search, no sortable columns, no row selection, no bulk status change, no pagination, no prev/next ticket navigation (only `← All tickets`). Working a queue means leaving the queue on every ticket. "Add condition" silently disables at 5 with no tooltip or count. Save with nothing changed returns a red error.

**Sam (accessibility-dependent)** — zero `aria-live` in the entire codebase: "Workflow saved.", "Analysis saved.", "Changes saved." are plain `<p>` — failure speaks, success is silent. Destructive arming has no `role="alert"`. Up to 5 buttons named literally "Remove". No `<th scope="col">` anywhere. Analytics chart collapses 30 data points into one `aria-label`; per-day values only in `title` (hover-only).
